- [Current upstream layout-control refresh](layout-control/upstream-refresh0.gpt6a.md):

- [Current Longcat implementation and control requirements](layout-control/longcat-current0.glm53m.md):
  episode/restoration semantics, the working niri precedent, newly usable Umbriel
  membership observations, and remaining axis, tab-unit and actuation decisions.

- [Activity service and journal replay](activity/service0.gpt6a.md): foreground
  user-service proposal, notify/watchdog crate choices, structured journal records,
  shared JSONL/NDJSON/logfmt output and history re-emission. Work anchor:
  `umbrs-activity`; only the five-second default is commissioned immediately.
  [Tracing-native records and capability inventory](activity/records0.gpt6a.md)
  refines the delivery order around the selected tracing-journald architecture,
  structured fields, selected metadata updates, JSON/logfmt/OSC layers and an
  AM-to-XH notify handoff. [Prior journald/tracing/OSC work](activity/prior-art0.glm53fx.md)
  surveys normal and hidden design/doc homes, identifying Cyclrs's implemented
  journal write/read mechanisms and the OSC protocol precedents.
- [Layout-control needs — Longcat, Umbriel and Kubeless](layout-control/longcat-needs0.gpt6a.md):
  the implemented consumer's missing native facts and operations; separates
  compositor changes from Rust-library ergonomics and Kubeless mechanisms.
  Compares observation-first, conditional group sizing and native reversible
  tokens, with owner-specific landing steps and acceptance evidence. Scheduler
  fairness stays deferred; none of these proposals is an implemented protocol.
  [Noctalia shell capabilities](layout-control/noctalia0.glm53max.md) surveys
  the other major Umbriel IPC consumer: the v5 shell's control path, its
  absent core layout control, the official companion plugin that does layout
  control over the same wire, and the services Noctalia itself exports.
